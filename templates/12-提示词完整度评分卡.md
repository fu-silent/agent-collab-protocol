# 模板 12 · 提示词完整度评分卡（Prompt Completeness Card）

> 用途：发送任务前 2 分钟自检；也可让 Agent 在开工前给你打分并列出缺口。
> 计分：每项 0/1/2（0=缺失，1=含糊，2=明确可执行），共 20 项，满分 40。
> 门槛：**<20 先澄清；20–29 可开工但需方案确认；30–35 良好；36–40 理想**。
> 风险联动：**R2+ 任务建议 ≥30；R3 任务建议 ≥34 且必须人工复核缺口**。

---

## A. 意图（Intent）— 8 分

| # | 检查项 | 0 | 1 | 2 |
|---|---|---|---|---|
| 1 | 背景与触发（现象/需求来源/证据） | 无 | 只有结论 | 有证据与影响 |
| 2 | 目标（一句话成功定义） | 无 | 笼统 | 具体可判定 |
| 3 | 受众与使用场景 | 无 | 泛泛 | 明确谁/何时用 |
| 4 | 成功度量或判定人 | 无 | 只有"好用" | 指标/判定标准 |

## B. 边界（Boundary）— 12 分

| # | 检查项 | 0 | 1 | 2 |
|---|---|---|---|---|
| 5 | 范围 In（改哪里） | 无 | 大概 | 文件/模块/页面明确 |
| 6 | 非范围 Out（不做什么） | 无 | 一句"别乱改" | 明确排除项 |
| 7 | 约束（技术/兼容/合规/风格/时间） | 无 | 部分 | 完整且可执行 |
| 8 | 输入与权威源（含冲突优先级） | 无 | 给了链接 | 明确权威与优先级 |
| 9 | 假设与未知（允许自主的边界） | 无 | 隐含 | 显式列出 |
| 10 | 风险与不可逆点 | 无 | 含糊 | 点名动作与影响 |

## C. 交付（Delivery）— 12 分

| # | 检查项 | 0 | 1 | 2 |
|---|---|---|---|---|
| 11 | 交付物（形式/位置/命名） | 无 | 大致 | 明确 |
| 12 | 验收标准（逐条可判定，含边界/负例） | 无 | 只有主路径 | 主路径+边界+反例 |
| 13 | 证据等级（E1–E4）与形式 | 无 | "给证据" | 指定等级与内容 |
| 14 | 质量门槛（测试/lint/评审/文档） | 无 | 部分 | 明确命令与标准 |
| 15 | 批次/里程碑（一次交付多少） | 无 | 隐含 | 明确分批与检查点 |
| 16 | 依赖/时间/时间盒 | 无 | 大概 | 明确 |

## D. 协作（Collaboration）— 8 分

| # | 检查项 | 0 | 1 | 2 |
|---|---|---|---|---|
| 17 | 授权边界（自主/须批准/禁止） | 无 | 含糊 | 逐项列明 |
| 18 | 流程模式（先方案→确认/直接做/只审查/分阶段） | 无 | 隐含 | 明确 |
| 19 | 报告格式与频率 | 无 | "做完说一声" | 六件套+停点报告 |
| 20 | 停点与升级（何时停、找谁、带什么） | 无 | 部分 | 明确 |

---

## 评分后的动作

| 分数 | 动作 |
|---|---|
| <20 | 不要开工；先问 3–5 个关键问题（给推荐答案） |
| 20–29 | 可开工，但必须先给方案/假设清单，人工确认后执行 |
| 30–35 | 正常执行；R2+ 仍需方案闸门 |
| 36–40 | 可直接执行；R3 仍需独立复核与回滚预案 |

## 一分钟 8 问（日常精简版）

1. 一句话目标是什么？2. 怎么判定成功？3. 明确不做什么？4. 依据哪份权威源？
5. 交付什么、证据要什么？6. 哪些动作不能自主/不可逆？7. 授权到哪一步？8. 卡住找谁？

> 8 问里有 2 个以上答不上来，就先别发任务；把问题抛回去，让 Agent 给选项与推荐。

## 让 Agent 自检（可直接粘贴）

```text
开工前，请按《提示词完整度评分卡》给我的需求打分（20 项，0/1/2），
列出得分 <2 的项与缺失信息；给出你准备采用的假设（逐条），
并只提不超过 5 个必须由我回答的问题（每个附推荐答案）。
```

## 附：结构 Lint（与手册 §5.8 同一份清单）

| # | 检查 | 不合格信号 | 修法 |
|---|---|---|---|
| L1 | 有无自相矛盾的要求？ | 多来源拼接、前后冲突 | 删/合并冲突项，或写清优先级 |
| L2 | 有无不可判定的模糊词？ | "更好、稳定、专业、尽快" | 换成可测标准或判定人 |
| L3 | 有无输出契约？ | 没说形式/位置/语言/格式 | 补交付物字段 |
| L4 | 有无验收与证据要求？ | "做完告诉我" | 补 AC 与证据等级 |
| L5 | 有无停止/升级条件？ | 无预算、无停点、失败继续试 | 补 stop conditions 与轮次上限 |
| L6 | 有无冗余上下文？ | 大段粘贴仓库可查内容 | 改为路径/链接，按需加载 |

## 附：两个可选参数（建议 R2+ 写明）

- `autonomy_level`：lean（只做列出步骤）/ standard（可自行拆解但不扩范围）/ thorough（可探索与自我纠错）。
- `tool_budget`：工具调用次数、时间、文件数或轮次上限；到 80% 必须报告并交回用户。

这两个参数用来替代"你随意/你看着办"：给自主空间，同时给边界与停点。
