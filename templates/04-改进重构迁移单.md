# 模板 04 · 改进 / 重构 / 迁移单

> 适用：行为基本不变但结构要改（重构）、体验/性能要提升（改进）、技术栈或数据要迁移。
> 核心原则：**先定义不变量，再谈改动**；没有基线的"改进"无法验收。

---

## 1. 改进动机与基线（Baseline）
- 现状指标：性能、可维护性、缺陷率、构建时间、可读性评分…（改前先测/先记录）。
- 痛点证据：哪个具体场景/哪次事故/哪段代码。
- 目标指标与阈值（改后达到什么算成功）。

## 2. 不变量（Invariants）★
- 行为不变的部分：对外接口、数据格式、错误码、页面结构、文案、性能下限…
- 约束：兼容版本、数据迁移窗口、依赖冻结。
- 验证方式：现有测试/回归脚本/对比工具/双跑。

## 3. 范围与非范围
- 改哪些模块/文件；明确不做哪些"顺手优化"。
- 允许的中间状态（是否可分批合并；是否保持随时可回滚）。

## 4. 方案对比（R2+ 必填）
| 方案 | 做法 | 优点 | 代价/风险 | 回滚难度 | 结论 |
|---|---|---|---|---|---|
| A | | | | | |
| B | | | | | |

- 决策记录：选择理由 + 被否决理由（见模板 06）。

## 5. 迁移/切换计划（如涉及）
- 阶段：准备 → 双写/双跑 → 切流 → 观察 → 清理。
- 回滚触发条件与步骤（谁在什么时候执行）。
- 数据校验：条数、抽样、校验和、业务核对。

## 6. 验收标准
| 编号 | 内容 | 证据 |
|---|---|---|
| AC-1 | 不变量全部保持 | E2：回归套件/对比报告 |
| AC-2 | 目标指标达到 ____ | E2：前后对比数据 |
| AC-3 | 回滚演练成功（R3） | E4：演练记录 |

## 7. 风险
- 高风险点、影响面、观察窗口、告警与监控项。

## 8. 常见错误
- 没有基线就改 → 无法证明"更好"。
- 只写"要做的事"，不写不变量 → 智能体顺手改变行为。
- 大爆炸式替换，没有中间可回滚状态。
- 迁移只验新系统，不验旧数据。

## 9. 最小可用版（小重构）
