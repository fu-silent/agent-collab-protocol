# 模板 06 · 方案 / 决策记录（ADR-lite）

> 适用：需要"先方案后执行"的中大型任务（R2+），或任何值得留痕的取舍。
> 目的：让决策可追溯、可复审，而不是埋在聊天记录里。

---

## 1. 背景与问题
- 要解决什么；为什么现在决策；相关约束。

## 2. 备选方案
| 方案 | 核心做法 | 优点 | 缺点 | 成本/工期 | 风险 | 可逆性 |
|---|---|---|---|---|---|---|
| A | | | | | | |
| B | | | | | | |
| C（不做的现状） | | | | | | |

## 3. 决策
- 选择：____
- 理由：____（对照目标与约束，而不是"感觉"）
- 被否决方案的原因：____
- 决策人 / 日期 / 参与人。
- 状态：proposed / accepted / superseded / deprecated（被取代时保留本文件并标注）。
- Supersedes：____；Superseded-by：____。

## 4. 影响与代价
- 影响面（模块/用户/流程/文档）；需要谁配合。
- 技术债或后续工作（明确登记为待办）。

## 5. 回滚/复审条件
- 什么信号出现时回滚或重新评估；复审时间点。

## 6. 执行约束（给执行者）
- 不可违反的约束；必须保持的不变量；验收标准。
- 允许执行者自行决定的范围（减少反复请示）。

## 7. 常见错误
- 只写"选择 A"不写"为什么不选 B" → 半年后重开辩论。
- 没有记录决策人与日期 → 无法追责/追溯。
- 方案文档与代码脱节 → 决策失效无人知。
- 方案粒度太细（把实现细节写死），执行者无法优化。

## 8. 最小可用版

```text
【问题】____【约束】____
【方案】A：____（优/缺/风险）；B：____
【决定】选 A，因为 ____；不选 B 因为 ____
【影响】____【回滚条件】____
【决策人/日期】____
```
