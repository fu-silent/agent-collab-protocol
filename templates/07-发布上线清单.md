# 模板 07 · 发布 / 上线清单

> 适用：代码发布、文档发版、站点上线、数据迁移生效等。
> 原则：**发布是高风险动作**（R3）：先确认元数据，再验证，再授权，最后回滚预案就绪。

---

## 1. 发布前（Pre-flight）

- [ ] 目标版本号/版次/日期已确认（时区、跨月规则）
- [ ] 变更清单（谁改了什么、影响哪些用户/语言/平台）
- [ ] 全量自检通过：测试、lint、构建、内容校验
- [ ] 产物已重建且与源一致（无未提交/未构建差异）
- [ ] 发布说明（Release notes / changelog）已写
- [ ] 关键链接/资源/资产可用（链接实测 200）
- [ ] 回滚方案与负责人已确认
- [ ] 通知相关人（支持/客服/团队）

## 2. 发布元数据（易错项）
- 版本号：____；版次：____（如"2026年11月第1版"）
- 发布日期：____（本地时区 vs 平台 UTC，确认差值）
- 产物清单与数量：____（如 7 份 PDF / 78 个页面）
- 发布渠道：____（正式站/预览站/商店/内部）

## 3. 执行步骤（按项目流程填写）

1. ____
2. ____
3. ____

> 每步都要明确：谁执行、失败怎么办、是否可跳过。

## 3.5 渐进发布（R3 建议）

- [ ] 灰度/试点范围（用户/流量/区域）：____
- [ ] 停止指标与阈值（错误率/延迟/业务指标）：____
- [ ] 前滚（roll-forward）方案：____；回滚方案：____
- [ ] 观察窗口：____；谁有权停止：____

## 4. 发布后验证（Post-release）

- [ ] 线上核心路径可用（首页/关键功能/下载链接）
- [ ] 版本/日期/资产数正确（与发布前记录逐项比对）
- [ ] 缓存场景：用 cache-bust 参数或不同网络确认
- [ ] 监控/日志无异常峰值
- [ ] 用户可见文案与本地化正确
- [ ] 记录验证证据（URL、时间、截图、命令输出）

## 5. 回滚预案

- 触发条件：____
- 回滚步骤：____（命令/操作人/预计耗时）
- 数据回滚：____（如涉及）
- 回滚后验证：____

## 6. 发布后 24–48 小时
- [ ] 观察指标：错误率、性能、反馈
- [ ] 事故/异常复盘（如有）→ 规则回写（见模板 11/12 与手册第 10 章）

## 7. 常见错误
- 发布日期按"今天"随手填，与平台实际时间差一天（跨 UTC 日界）。
- 发布前没重建产物 → 线上是旧内容。
- 只验本地，不验线上/缓存。
- 回滚预案只存在脑子里。
- 发布后不核对元数据（版本号、资产数、日期）。

## 8. 最小可用版（小发布）

```text
【版本/日期】____
【变更】____
【发布前】测试/构建/链接/资产 已验（E2）
【步骤】____
【发布后】线上核心路径 + 版本/链接核对（E3）
【回滚】____
【授权】我说"发布"才执行；每步结果回报。
```
