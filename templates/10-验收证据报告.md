# 模板 10 · 验收报告与证据附件

> 适用：任何"完成"的交付。核心：**结论先行、逐条对账、证据可复现、未验证项显式声明**。
> 规则：没有证据的"完成"= 未完成（见手册"证据阶梯"）。

---

## 一、结论（Conclusion）
- 一句话：完成了什么，是否可以进入下一步（可验收/可合入/可发布）。
- 任务 ID 与契约版本：____（对应哪份契约/需求单）
- 风险提示：____。

## 二、改动清单（Change list）
| # | 文件/对象 | 改动内容 | 原因 |
|---|---|---|---|
| 1 | `path:line` | | |

## 三、验收对账（Acceptance matrix）★

| 验收标准 | 要求证据等级 | 实际证据 | 结果 |
|---|---|---|---|
| AC-1 ____ | E2 | 命令/输出/链接 | ✅/❌ |
| AC-2 ____ | E2 | | |
| AC-3（边界/负例） | E2 | | |

> 每条必须能点开/复现；不允许"已测试"这种无证据结论。

## 四、证据附件（Evidence）

- **命令与输出**：`____` → 原始输出（截断处说明）
- **指标/计数**：____（前后对比）
- **线上/环境验证**：URL、时间（含时区）、HTTP 状态、`Last-Modified`
- **环境**：版本/依赖/数据/时区/设备：____
- **截图/录屏**：路径与说明（截图不能替代可断言证据，只作辅助）
- **失败尝试**：尝试过什么、为什么失败（如实；缺陷类须给修复前红、修复后绿）
- **证据新鲜度**：证据对应的 commit/时间：____（旧证据视为未验证）

## 五、未验证 / 待核实（Explicit gaps）
- [ ] ____（为什么没验、怎么验、风险）
- 明确声明：以上之外的范围均未验证。

## 六、风险与遗留
- 已知风险：____；缓解措施：____
- 副作用与回滚：数据/配置/外部状态影响；回滚命令或步骤：____
- 遗留 TODO：____（登记位置）
- 需要谁跟进：____

## 七、推送/发布状态
- 本地提交：____（commit 哈希）；是否推送：**未推送 / 已推送至 ____**
- 是否需要发布：是/否；发布前还需：____

## 八、下一步建议
- 建议动作：____；需要谁批准：____。

---

## 证据自检清单
- [ ] 每条验收标准都有证据，且等级达标
- [ ] 证据是"命令+输出/指标"，不是"我确认过"
- [ ] 边界与负例至少各 1 条（R1+）
- [ ] 未验证项没有遗漏
- [ ] 改动清单与实际 diff 一致
- [ ] 推送状态明确
- [ ] 相关规范/文档/交接已回写

## 反例
- "已全部完成，测试通过"（无命令无输出）
- 只贴成功日志，不贴失败尝试
- 验收标准被悄悄改简单了（"基本可用"）
- 说"七语言已同步"，但没有逐语言计数
