# 模板 11 · 项目 Agent 指令（AGENTS.md 风格）

> 用途：把"团队对这个项目里 Agent 的长期要求"写进仓库根目录，跨会话生效。
> 依据：AGENTS.md 是开放的 Agent 指令格式（agents.md，已被 6 万+ 开源项目采用）；原则是
> "最靠近目标文件的 AGENTS.md 优先，用户的即时聊天指令覆盖一切"。
> 适用工具：Claude Code、Codex、Cursor、Amp、Jules、Gemini CLI 等（大多自动读取）。

---

## 建议结构（按需裁剪，只写 Agent 真正需要且 README 不写的）

```markdown
# AGENTS.md

## 项目概览
- 一句话：____
- 目录地图：____ → ____
- 技术栈/版本：____

## 不可协商原则（项目宪法）
- 安全/合规红线：____
- 权限与密钥：____
- 发布/合并规则：____
- 违反时的停止与上报：____

## 环境与命令
- 安装：`____`
- 构建：`____`
- 测试：`____`（单个测试：____）
- lint/类型检查：`____`
- 本地运行：`____`
- 其他：代码生成、数据库迁移、格式化

## 规范与约定
- 代码风格：____（如"严格模式、单引号"）
- 提交信息格式：____
- 分支/PR 规则：____
- 文档/注释要求：____

## 权限与红线（重要）
- 可自主：读文件、跑测试、本地 commit
- 须批准：推送、发布、删除、改权限、外发消息、动历史
- 禁止：____
- 密钥/隐私：____

## 工作流
- 默认流程：先方案 → 确认 → 执行（R2+）
- 验收：必须附命令+输出+数值；声明未验证项
- 停点：发布前必须停；遇到范围外问题先报告

## 验证清单
- 改动后必须跑：`____`
- 提交前必须跑：`____`
- 交付报告必须包含：改动清单 / 证据 / 未验证项 / 推送状态

## 已知坑
- ____（链接到详细文档）
- 不要做的事：____

## 需要读的文档
- 规范：`README.md` 第 __ 节
- 设计/决策：`docs/____`
- 变更记录：`CHANGELOG.md`
```

## 写法建议

1. **只写"Agent 会犯错且 README 不写"的内容**；不要复制 README。
2. **命令要可复制执行**；给"单测怎么跑"这类高频命令。
3. **红线要具体到动作与路径**（"不要改 `dist/`"而不是"小心构建产物"）。
4. **保持短**：先 30–80 行；随事故增补，不写作文。
5. **就近放置**：monorepo 可在子目录放第二个 AGENTS.md（最近的生效）。
6. **与即时指令的关系**：AGENTS.md 是默认值，用户在对话里的明确要求优先；冲突时提醒用户。

## 维护规则

- 每次因 Agent 犯错而新增规则时：先修当次问题 → 再提炼一条通用规则 → 写入 AGENTS.md（或项目规范）。
- 每季度清理一次过时条目；版本化（随代码提交）。
- 与其他 Agent 工具的同类文件（CLAUDE.md、.cursor/rules、技能 SKILL.md）保持一致：同样的规则只维护一份"真源"，其他文件引用/同步。
