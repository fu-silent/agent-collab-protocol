# 模板 03 · 缺陷 / 问题报告单（Bug Brief）

> 适用：线上或本地出现异常、行为与预期不符、回归问题。
> 核心：**先复现，再定位，再修复，最后回归验证**。没有复现步骤的 bug 单 = 猜测。

---

## 1. 现象（Symptom）
- 发生了什么（用户可观察到的表现），不要先猜原因。
- 影响范围：谁/多少人/哪些环境/是否阻塞。

## 2. 复现步骤（Reproduction）
1. 环境：版本/commit、OS、浏览器/设备、配置、数据状态。
2. 步骤：最小可复现序列（编号）。
3. 期望结果 vs 实际结果。
4. 复现率：必现 / 偶现（约 N 次中出现 M 次）。

## 3. 证据（Evidence）
- 报错日志/截图/录屏/请求响应/监控数据；时间点与时区。
- 反证：确认不是缓存、代理、账号权限、数据特例。

## 4. 影响与优先级
- 严重度（数据丢失/安全/阻塞/体验）与紧迫度；是否有临时绕行方案。

## 5. 初步定位（Hypothesis，可选）
- 怀疑的模块/提交/依赖；依据是什么；不要当作结论。

## 6. 修复约束
- 必须保持不变的既有行为（不变量）；
- 可以改动的范围；
- 是否需要回归测试、迁移、兼容处理。

## 7. 验收标准
| 编号 | 内容 | 证据 |
|---|---|---|
| AC-1 | 原复现步骤不再出现 | E2：原步骤录屏/测试通过 |
| AC-2 | 相邻功能未回归 | E2：相关测试套件通过 |
| AC-3 | 根因有说明（不是只修表象） | E1：说明+diff |

## 8. 根因与修复记录（修复后填）
- 根因：触发条件 → 机制 → 结果。
- 修复方式；为什么不是"只修表象"。
- 预防：是否需要加测试/校验/文档/规范。

## 9. 常见错误
- 描述现象时夹带原因判断，误导定位。
- 没有最小复现，智能体只能"猜着改"。
- 修完只验原步骤，不验相邻与负例。
- 只修 bug 不补回归测试，下次复发。

## 10. 最小可用版

```text
【现象】____（期望 ____，实际 ____）
【复现】1) ____ 2) ____ 3) ____；环境 ____；复现率 ____
【证据】____（日志/截图/链接）
【范围】只改 ____；不要动 ____
【验收】原步骤通过 + 相邻回归通过（E2）
【授权】修复与本地提交可自主；发布等我说。
```
