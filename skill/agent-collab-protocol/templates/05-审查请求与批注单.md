# 模板 05 · 审查请求与批注单

> 适用：让智能体审查代码/文档/方案；或你审查智能体的产出。
> 原则：**审查只读、结论分级、证据可追溯、逐项裁决**。审查不是"再生成一遍"。

---

## A. 发起审查（人类 → 智能体）

**1. 审查对象**
- 范围：文件/目录/提交/PR/文档章节；基准版本（commit/tag）。
- 重点：正确性、安全性、一致性、可维护性、性能、文风…

**2. 审查标准（权威源）**
- 依据哪些规范/约定/验收标准；冲突时谁优先。
- 严重度定义：Blocker / Major / Minor / Nit（或 P0/P1/P2/P3）。

**3. 输出要求（只读，不改）**
- 编号清单：`位置 | 现状 | 应为 | 依据 | 严重度 | 建议动作`
- 每条给出可验证依据（文档条款/测试/复现步骤）；无法确认的标"待核实"。
- 最后给：总体结论（可合入/需修改/需重做）+ 未覆盖范围。

**4. 边界**
- 本轮只审查不修改；修改须另行批准。
- 不评论范围外内容；发现范围外问题单列"附注"。

---

## B. 人类批注（用于逐项裁决）

```text
M1 改（按建议）；
M2 保留（理由：____）；
M3 补依据后再说；
M4 改为 ____；
O1/O2 纳入待办；
其余暂缓。
只做以上最小集合；完成后给改动清单与证据；不要推送。
```

**批注规则**
- 用智能体的编号，不另起一套；用"改 / 保留 / 补依据 / 搁置 / 放弃"五种状态。
- 一次给完，避免"挤牙膏"式来回。
- 单点错误 → 提炼通则 → 问"要不要写进规范"。

---

## C. 审查报告模板（智能体 → 人类）

**结论**：可合入 / 需修改 / 需重做（一句话理由）。

| 编号 | 位置 | 现状 | 应为 | 依据 | 严重度 | 动作 |
|---|---|---|---|---|---|---|
| M-1 | | | | | | |

**已验证**：____（命令/证据）
**未验证 / 待核实**：____（原因）
**附注（范围外）**：____
**建议后续**：____

---

## D. 常见错误
- 审查变成"重写"（直接改文件，人类失去裁决机会）。
- 只给结论不给证据（"这里不好"）。
- 严重度通胀（全是 P0）或全无分级。
- 漏报"未覆盖范围"，让人误以为全审过。
- 人类批注不完整（"看着改吧"）→ 智能体自由发挥。

## E. 最小可用版

```text
请只审查 ____（基准 ____），按 ____ 规范，输出编号清单（位置/现状/应为/依据/严重度）。
只读不改；无法确认标"待核实"；给总体结论与未覆盖范围。
```
